# 展会临时电表离线出账工作区

在**不修改采集器、不重新采集、不触碰跨届身份名册**的前提下，对一届已验收的
展会做离线出账：给定全目录采集报告（只用来确认本届展位编号）、表计日志、
归属表、出账批次上界和连续的 UTC 自然日范围，交付可入数仓的**逐日电量结算**
及**随账明细**。纯 Python 标准库、完全离线；建议始终用 `python3 -I` 运行。

## 1. 目录结构

```
billing_workspace/
  billing/
    extmem.py      # 磁盘后备外部排序（分块内排 + 多路归并）
    settle.py      # 核心：日志版本解析、归属校验、逐表流式结算、原子交付、独立核验
    cli.py         # 命令行入口（run / show / verify）
  scripts/
    bill           # 自带路径引导的可执行入口（-I 下可直接用）
    run_demo.sh    # 可复跑端到端演示
    verify_all.sh  # 单测 + 演示 + 核验 一键复跑
  tests/test_billing.py
  examples/        # 小体量示例输入（行序故意打乱，含修订/撤销/重复/越界批次）
  demo_out/        # 演示产物（运行 run_demo.sh 生成，可随时删除重建）
```

## 2. 输入

* **采集报告**（`--report`）：现有格式的全目录采集报告。只接受
  `complete=true` 且根筛选为空的报告；展位 `id` 非空且不重复。
  报告只用来确认本届展位编号，不重新采集，也不读取名册工作区。
* **表计日志**（`--meter-log`，逐行 JSON）：每行是某只表、某个读数编号的
  一个修订，行可乱序：
  ```json
  {"meter":"M1","reading":"r3","batch":2,"time":1740808800,"period":"P1","wh":2200}
  {"meter":"M1","reading":"r99","batch":3,"revoke":true}
  ```
  `batch` 为非负整数；有效（upsert）行另有整数 Unix 秒 `time`、计数周期标识
  `period`、非负整数累计瓦时 `wh`；撤销行带 `"revoke":true` 且不得再携带
  读数字段。字段严格，未知字段、类型错误、负值都按格式错误整次拒绝。
* **归属表**（`--attribution`，逐行 JSON）：
  ```json
  {"meter":"M1","booth":"B01","start":1740700800,"end":1740960000}
  ```
  左闭右开整数秒区间；同一只表的区间不得重叠（相邻相接允许），空档即未归属。
* **参数**：`--batch-bound` 出账批次上界（非负整数）、`--from/--to`
  连续 UTC 自然日（含首尾）、`--max-gap-seconds` 财务给定的最大可结算
  间隔（正整数秒）、`--out` 输出目录、`--work-dir` 可选磁盘临时空间。

## 3. 版本解析与校验（任何错误都整次拒绝，不留半份账单）

* 同一只表的同一读数编号，只取**不超过批次上界的最新修订**；最新可见修订
  是撤销则该读数不存在；修订可以改变抄表时间。越界批次完全不参与。
* 可见修订中，同表、同编号、同批次内容相同的重复行只算一次；内容冲突
  （含撤销与 upsert 同批次并存）整次拒绝。
* 选定版本后同一只表仍有两条读数占用同一秒 → 报错；同计数周期内相邻
  （按时间序）读数累计值倒退 → 报错。跨周期的相邻读数不检查倒退。
* 归属表中的未知展位（不在本届报告里）、无效区间（start ≥ end）、同表
  区间重叠 → 报错。

## 4. 结算语义

* 每只出现在有效读数或归属表中的电表，都要对所选日期内的全部时间交代
  清楚：时间相邻的两条读数在**同一计数周期**且距离 **≤ 最大间隔秒数** 时，
  两读数之间的左闭右开区间才可结算，电量 = 累计值之差；其余时间
  （跨周期、过长间隔、首条读数之前、末条读数之后）一律计为缺测，不补读数。
  计数相同的合格区间是**实测到零**（已知 0 瓦时），不是缺测。
* 每段可结算区间按**完整区间**中各「UTC 日期、展位或未归属」实际占用秒数
  的比例分配整数瓦时：同一组合分开出现时先合计秒数；各组合先取整数下限，
  剩余瓦时按小数余量从大到小每组补一瓦时；余量相同先给日期较早者，同日
  按展位编号字典序、未归属排在实际展位之后。
* **只发布所选日期的分配**，但分配在完整区间上计算，与出账窗口无关——
  同一天单独出账或并入多天出账，分到的电量相同；截在窗口外的抄表时间和
  归属仍可能影响本期（演示第 4 步逐字节验证这一点）。

## 5. 输出（`<out>/bill-NNNNNN/`，序号递增，`CURRENT` 指向最新成功结果）

| 文件 | 内容 |
| --- | --- |
| `summary.jsonl` | 逐日汇总：`{"date","booth"(未归属为 null),"known_wh","missing_meter_seconds"}`，按 (日期, 归属) 排序；两只表同时缺测一秒算两表秒；只交付窗口内实际有明细的键 |
| `known_details.jsonl` | 已知明细：表号、日期、归属、区间起止、左右读数编号及所用批次、该组合在完整读数区间里的占用秒数、所分瓦时（含零值） |
| `missing_details.jsonl` | 缺测明细：表号、日期、归属、区间；同表同日同归属的相邻缺测已合为一段 |
| `manifest.json` | 参数、输入文件 sha256、目录版本、各项计数 |

三类记录文件的行序与输入行序无关（全部外排为规范顺序）。明细按
(日期, 归属, 表号, …) 排序，未归属排在实际展位之后，便于逐键对回汇总。

## 6. 原子性与内存模型

* 全部产物先写 `<out>/.staging-*`，全流程成功才原子改名为
  `bill-NNNNNN/` 并切换 `CURRENT`；任何输入错误都会清理暂存，
  **上次成功结果原样保留**，历史账单目录不可变。
* 表计日志、单表历史、明细都可大于内存：日志逐行规范化后外排，读数按
  (表, 时间) 外排后逐条流过（内存里只保留上一条读数），已知与缺测分两趟
  各自流式、归属游标随时间轴单向前进，明细先落盘再外排，汇总由贡献流
  外排归并。除本届展位编号集合与单个可结算区间内的 (日期,归属) 秒数聚合
  （上界受最大间隔限制）外，不整批或整只表载入内存；临时分块写在
  `--work-dir`（默认输出目录下自建自清）。

## 7. 用法

```bash
python3 -I scripts/bill run \
  --report ../booth_collector/out/S1_complete.json \
  --meter-log examples/meter_log.jsonl \
  --attribution examples/attribution.jsonl \
  --batch-bound 5 --from 2025-03-01 --to 2025-03-02 \
  --max-gap-seconds 14400 --out ./demo_out

python3 -I scripts/bill show --out ./demo_out      # 当前账单（CURRENT 指向）
python3 -I scripts/bill verify ./demo_out          # 独立核验：明细逐项对回汇总
python3 -I scripts/bill verify ./demo_out/bill-000001
```

错误（报告不验收、日志格式/冲突、归属非法、读数同秒/倒退、参数非法）
一律以退出码 2 返回 `{"ok": false, "error": ..., "message": ...}`。

## 8. 复跑方式

```bash
bash scripts/verify_all.sh          # 单测 + 端到端演示 + 独立核验
python3 -I tests/test_billing.py    # 仅机制级单测（44 组，含朴素参照随机对拍）
bash scripts/run_demo.sh            # 仅演示
```

示例输入是小体量手工构造数据（含修订改时间、撤销、重复行、越界批次、
窗口外读数）；测试中的大批量数据在临时目录现造现删，不进仓库。

## 9. 需求对应要点

| 要求 | 落实位置 |
| --- | --- |
| 报告只确认本届展位编号，不重新采集、不改名册 | `load_accepted_report`（与名册同一套验收标准） |
| 批次上界内最新修订、撤销即不存在、修订可改时间 | `_resolve_readings` |
| 同批次重复行去重、内容冲突整次拒绝 | `_resolve_readings` 的批次组检查 |
| 未知展位/无效区间/同秒两读数/同周期倒退均报错 | `_normalize_attr_line`、`_check_attr_overlap`、`_settle_meter` |
| 同周期+距离≤上限才可结算，其余缺测；零差是实测到零 | `_settle_meter`、`_emit_known_interval` |
| 完整区间按 (日期,归属) 秒数比例分整数瓦时；先合计、下限+余量、平局规则 | `_allocate` |
| 只发布窗口内日期；单日/多日结果一致 | 分配与窗口解耦；`tests` 与演示第 4 步验证 |
| 汇总键=日期+展位（含未归属），缺测按表秒累计 | `_build_summary` |
| 明细逐项对回汇总；已知列左右读数/批次/占用秒/瓦时；缺测相邻合并 | `known/missing_details.jsonl`、`verify_bill` |
| 只交付有明细的汇总键 | 汇总由明细贡献归并产生 |
| 输入行序无关 | 全链路外排为规范全序，`DeterminismAndAtomicityTest` |
| 失败不留半份账单、不覆盖上次成功 | 暂存目录 + 原子改名 + `CURRENT` 切换 |
| 日志/单表历史/明细可超内存 | `extmem` 外排 + 逐表流式主流程 |
| 本地用法与可复跑示例；大数据不进仓库 | README、`examples/`、`run_demo.sh`、测试临时目录 |

## 10. 已知边界

* 出账目录的序号分配与 `CURRENT` 切换面向单进程使用，不做多进程并发互斥；
* 归属空档一律按未归属结算，不做跨届身份推断（名册工作区的事，这里不碰）；
* 单只表在单个可结算区间内的 (日期,归属) 组合数受最大间隔秒数限制，
  财务给定的间隔若极大，该区间聚合一步的内存随之增长（其余环节仍流式）。
