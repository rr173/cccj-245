# 离线展会目录采集器（本地模拟服务 · 固定版本 · 预算可核对）

纯 Python 标准库实现，无任何网络访问、无第三方依赖。采集器只对一个本地
模拟服务发请求，服务持有一份**固定版本**的展会目录；版本号是目录全部
展位（ID/标签/内容）规范化后的 SHA-256 前缀，任何内容变化都会改变版本。

## 1. 服务契约（`boothlib/service.py`）

请求 = 一个合取筛选（有限标签上的「必须有 / 必须没有」）+ 页大小 k。
每次响应返回：

| 字段 | 含义 |
| --- | --- |
| `filter` | 规范化回显的筛选（include/exclude 排序后） |
| `version` | 目录版本，同一目录的所有响应必须一致 |
| `total` | 匹配该筛选的**精确**总数 |
| `rows` | `min(k, total)` 条**不同 ID** 的展位，含标签和内容，不保证顺序 |
| `truncated` | 返回行数是否少于总数 |

展位可以多标签、无标签。行的选取按「筛选 + 展位 ID」做确定性哈希排序，
因此不同筛选的探查会真实地重叠，且顺序与筛选相关。

故障注入全部显式、默认关闭：瞬态失败（重试计费）、总数虚报、版本漂移、
行内容/标签篡改、同请求重复 ID。

## 2. 核心方法（`boothlib/explorer.py`）

### MECE 分区树

对一个区域按分面标签 `t` 拆成两个子区域：

- 区域 + 必须有 `t`
- 区域 + 必须没有 `t`

该拆分对区域内展位**互斥且穷尽**：一个展位无论带几个标签（含零标签），
都恰好落入一侧。深度优先探查，只有在响应截断（`truncated`）时才继续拆分；
没有可用分面的截断区域标记为**不可细分截断**。

### 重叠探查与「旧行补足」

所有已确认响应里的行进入一个全局登记表（跨响应做 ID 身份/内容一致性
校验）。任何分区的已知成员 = 登记表中匹配该分区筛选的行，**可以来自
更早的重叠探查**（见 `tests/test_core.py::test_old_rows_fill_truncated_leaf`，
每个成员都能回溯到另一条已确认响应）。

**计数永不相加重叠探查**：分区计数只来自 (a) 该分区自己响应里的精确
`total`，或 (b) 已确认父子/兄弟计数的算术残差。重叠只用来补行，不用来
加计数。

### 预算与重试（`boothlib/client.py`）

- 每次服务调用（含失败重试、含被判定矛盾的调用）都计费并写入 `ledger`；
- 已确认的相同规范化请求走确认缓存，重放**免费**（`cache_hits` 可核对）；
- 预算耗尽即停，未到达区域标 `blocked`。

### 未完成时的保守界

每个叶子分区报告：有精确计数则精确对平（`missing_exact`）；否则给出
`missing_bounds = [下界, 上界]`——下界是已见不同 ID 数，上界只取父区/
同层兄弟已证实计数支持的残差，取不到则为 `null`（不编造）。全局界同理。

## 3. 矛盾检测（区分三类终止）

`termination_class` 取值：`completed` / `unsplittable_truncation` /
`budget_exhausted` / `budget_exhausted_with_unsplittable_truncation` /
`response_contradiction`。

采集器与核验器至少检查：

1. 行是否匹配其请求筛选；
2. 同请求计数：行数 = `min(k,total)`、行数 ≤ 总数、ID 互不重复；
3. 父子计数：MECE 子区计数之和必须等于父区精确计数；
4. 已见不同 ID 是否超出分区精确计数；
5. 版本是否全部一致；
6. 同一 ID 跨响应的标签/内容是否恒定（身份漂移）；
7. 每个已见展位在叶子分区中是否恰好归属一个叶子（MECE 成员证明）。

存在任何矛盾都**不得宣告完整**，也不推断任何未观察到的目录内容。

## 4. 独立核验（`boothlib/verifier.py`）

核验器拿到报告与同一份目录夹具后，自建全新服务/客户端，独立重放报告中
的全部请求，执行 16 项检查（V1–V11：版本、账本/预算、请求契约、身份、
逐展位 MECE 证明、计数对平、容量、根范围、界的保守性、完整性结论）。
报告的 `complete=true` 只有在核验器独立证明所有叶子零缺失时才成立。

## 5. 复跑方式

```bash
cd booth_collector
bash run_all.sh                       # 一键：夹具→9 场景→单测→独立核验
# 或分步：
python3 -I scripts/build_fixtures.py  # 生成 fixtures/*.json（含内容哈希版本）
python3 -I scripts/run_demo.py        # 生成 out/S1..S6 报告
python3 -I tests/test_core.py         # 9 组机制断言
python3 -I scripts/verify_all.py      # 独立核验全部报告
python3 -m boothlib.verifier out/S4_budget.json fixtures/catalog_big.json
```

## 6. 场景与题目要求的对应

| 场景 | 覆盖点 |
| --- | --- |
| `S1_complete` | 小目录完整采集，叶子计数逐区对平到零缺失 |
| `S2_fill_truncated` | k=3 频繁截断；多标签/无标签/分面外标签（vip）并存；重叠探查的旧行补足已证实计数的分区 |
| `S3_unsplittable` | 无可用分面，根区截断且**不可细分**；只报精确缺失，不造行 |
| `S4_budget` | 预算 3 次用尽；未探区域只给父区/同层证据支持的保守界 |
| `S5a..S5d` | 虚报总数、版本漂移、行篡改（筛选不匹配+身份漂移）、重复 ID，均被识别为 `response_contradiction` |
| `S6_retry_cache` | 瞬态失败的重试计入预算（4 次计费 vs 3 个不同请求）；已确认相同请求免费重放 |

## 7. 目录结构

```
boothlib/
  model.py      筛选/展位/版本哈希
  service.py    本地模拟服务与故障注入
  client.py     预算账本、确认缓存、底层一致性检查
  explorer.py   MECE 分区树、保守界、终止分类、报告
  verifier.py   独立核验（16 项检查）
scripts/        夹具生成、场景运行、批量核验
tests/          机制级单元测试
fixtures/       固定目录夹具（可人工审计）
out/            各场景报告（含完整 ledger、分区、展位与矛盾明细）
```

## 8. 已知边界

- 探查计划是简单的深度优先按需拆分，**不追求全局最优**预算使用；
- 分面之外的标签（如 `vip`）只能随行走访，不能用于拆分；
- 所有结论只基于已确认响应与算术恒等式，不依赖对服务内部实现的了解
  （核验器虽然使用同一份夹具，但那是独立的核验证据，不是采集路径的一部分）。
