# 跨届复展名册本地工作区

在**不修改采集器、不重新调用服务**的前提下，从多届已验收的全目录采集报告
建立跨届参展商名册，并按人工身份更正，交付可直接应用到下游表的变更集。
纯 Python 标准库、完全离线、可反复打开；建议始终用 `python3 -I` 运行。

## 1. 目录结构

```
roster_workspace/
  roster/
    workspace.py     # 核心状态机：报告准入、身份组、依据台账、变更集、原子落盘
    cli.py           # 命令行入口（init/correct/replay/changes/show/log/verify）
  scripts/
    roster           # 自带路径引导的可执行入口（-I 下可直接用）
    run_demo.sh      # 可复跑端到端演示
    verify_all.sh    # 单测 + 演示 + 核验 一键复跑
  tests/test_roster.py
  examples/ops_batch.json
  demo_ws/           # 演示产物（运行 run_demo.sh 生成，可随时删除重建）
```

一个工作区在磁盘上就是：

```
<workdir>/
  state.json          # 届次、展位快照、依据台账、邻接、组件、当前名册、提交链
  changes/
    commit-0.json     # 初始化变更集（从空表写入的全量 upsert）
    <commit>.json     # 每批更正一份不可变变更集
```

## 2. 初始化：届次顺序与报告准入

`--edition 届次名=报告路径` 的**给出顺序就是从早到晚的届次顺序**，序号从 1
开始。只接受同时满足以下条件的现有格式报告：

* `complete == true`（拒绝预算耗尽、不可细分截断、矛盾类等非完整报告）；
* `root_filter.include/exclude` 均为空（拒绝带根筛选、不是全目录的报告）；
* 展位 `id` 为非空字符串且报告内不重复。

展位编号只在本届内有意义；**同名、同标签、编号相同都不会自动并组**——
`(届次序号, 展位编号)` 才是展位的全局身份。没有任何连接的展位也全部入册，
初始化时每个展位自成一个身份、一行名册。

```bash
python3 -I scripts/roster init ./ws \
  --edition "2024春=../booth_collector/out/S1_complete.json" \
  --edition "2024秋=../booth_collector/out/S2_fill_truncated.json" \
  --edition "2025春=../booth_collector/out/S6_retry_cache.json"
```

上例接入 3 届（S1=8、S2=16、S6=8 个展位），`S3/S4/S5*` 因不完整被排除。
初始化产生固定提交号 `commit-0`，变更集是从空表写入的全量 upsert。
报告只在初始化时读取，之后展位已快照进 `state.json`，**不再需要原报告在线**。

## 3. 身份更正：依据、连接与主标识

工作人员批量登记/撤回「两个展位属于同一参展商」的依据（evidence）：

* 每条依据有**全局不可复用的编号**，引用两个**不同且已收录**的展位
  （引用形式 `届次序号/展位编号`，如 `2/B07`）；
* 多条依据可以支持同一对展位；只要还有任一有效依据，这一对就保持相连；
* 身份按所有有效连接的**传递闭包**认定；撤回只是移除该依据的连接，
  **不是声明两家不同**；
* 一批内同一依据最多操作一次；登记已用编号、撤回不存在/已撤回的依据、
  未知展位、同展位自连等一律整批拒绝。

每个身份组的**主标识** = 该组最早出现届次中、字典序最小的展位编号。
名册行规则：每个身份在每个**实际参展届次**只出一行，列出该身份在该届的
全部展位编号，以及它实际参加过的**前一届**（首次为 `null`，缺席届次不补行）。

```bash
# 登记（可多条，可混用 --ops 文件）
python3 -I scripts/roster correct ./ws --commit c1 --base commit-0 \
  --register e1:1/B01:2/B01 --register e2:2/B01:3/B01
# 撤回
python3 -I scripts/roster correct ./ws --commit c3 --base c2 \
  --withdraw e2:2/B01:3/B01
# 文件批量：--ops examples/ops_batch.json（{"operations": [...]}）
```

> 表键唯一性：主标识由固定规则选举，若某批合并会让两个不同身份在同一届
> 共用 `(届次, 主标识)` 表键，该批会被明确拒绝（`bad_operation`）且状态
> 不变，避免下游表键撞车。

## 4. 变更集语义（下游可直接按序应用）

表键 = `(届次序号, 主标识)`。

* **初始化**：`deletes` 为空，`upserts` 为从空表写入的全部完整行；
* **此后每批**：只含相对上一批
  - `deletes`：已消失的键；
  - `upserts`：新增键，或键未变但内容（展位集合 / 前一届）改写的**完整行**；
  - 没变化的行不会再次出现；
* 即使本批没有名册变化（如为已连接的对补一条依据），也交付带
  `commit` 与 `base_commit` 两个提交号的空变更集，便于下游按序应用。

每批 `correct` 必须提供**新提交号**和**预期上一提交号**；预期上一提交号
不等于当前头部即按过期批拒绝，不改变任何已发布结果。

## 5. 同号重送（换进程、跨新批）

同提交号重送时，内容相等的判定为：`base_commit` 相同且**规范化操作集合**
相同——展位对去方向、操作排序后比较，**不计操作顺序与展位对方向**。

```bash
# 与 c1 同内容（对反方向、顺序调换），即使头部已到 c3，仍拿回原变更集
python3 -I scripts/roster replay ./ws --commit c1 --base commit-0 \
  --register e2:3/B01:2/B01 --register e1:2/B01:1/B01
```

同号不同内容、重送未知提交号均拒绝（退出码 2）。

## 6. 作用域处理（不遍历无关身份组）

更正只处理本批展位**批前或批后所属的身份组**：

* 批前作用域 = 本批展位当前所在组件（沿持久化组件表直接取成员）；
* 批后作用域 = 从同一批展位出发，沿「应用本批增量后的邻接视图」BFS 可达节点；
* 局部并查集只建在作用域展位与作用域邻边上；名册差异只在作用域行之间计算，
  无关组的展位、连接、名册行都不会被遍历或重发。

全量重放只用于独立核验（`verify`）这一诊断命令，不属于更正路径。

## 7. 原子性与中断重开

每批先把新变更集写到独立文件（不触碰已有文件），再用同目录临时文件 +
`os.replace` 原子替换 `state.json`。因此中断只会停在「变更集已写、状态未
推进」或更早，重开后头部仍指向上一提交、其变更集必然可读，不会出现
「身份已更正却取不回该批变更」的悬空状态。所有变更集不可变、可随时取回。

## 8. 独立核验与复跑

```bash
bash scripts/verify_all.sh          # 单测 + 端到端演示 + 独立核验
python3 -I tests/test_roster.py     # 仅机制级单测
python3 -I scripts/roster verify ./ws   # 从 state.json 全量重放所有提交，
                                        # 重算每个变更集并核对当前名册
python3 -I scripts/roster show ./ws     # 当前名册与依据台账
python3 -I scripts/roster log ./ws      # 提交链
python3 -I scripts/roster changes ./ws --commit c1   # 取某提交的变更集
```

`verify` 只依赖工作区自身快照，不读取任何原始采集报告，也不调用服务。

## 9. 需求对应要点

| 要求 | 落实位置 |
| --- | --- |
| 从早到晚届次顺序、每届一份现有格式报告 | `init` 的 `--edition` 顺序，序号 1..n |
| 拒绝非完整 / 带根筛选报告 | `_load_accepted_report` |
| 编号仅本届有效，不自动并组；无连接也入册 | 展位键 `(order,id)`，初始化各自成组 |
| 依据不可复用、引用两个不同已收录展位、多条支持一对 | `correct` 准入校验 + 依据台账 |
| 有效依据传递成组；撤回≠声明不同 | 邻接索引 + 局部 DSU；撤回只删该依据 |
| 主标识=最早届字典序最小编号 | `_primary_for` / `_rows_for_component` |
| 每实际参展届一行、列全部展位、前一届（首 null、缺席不补行） | `_rows_for_component` |
| 表键 (届次,主标识)；初始化全量、之后只发删除+改写、无变化不发、空变更仍交付 | `_diff_scoped` / `_publish` |
| 新提交号+预期上一提交号；旧提交、同号不同内容、未知展位、重复登记、撤回未生效均拒绝 | `correct` / `replay` |
| 同号同内容（去方向、忽略顺序）重送拿回原变更 | `replay` + 规范化摘要 |
| 一批内同一依据不操作两次；全有或全无 | 校验先于任何状态修改 |
| 只处理本批涉及身份组，不遍历无关组 | 作用域 BFS + 局部 DSU + 作用域差异 |
| 中断重开无悬空状态 | 变更集先落盘 + 状态原子替换 |
| 不改采集器、不重新调服务、无需原报告在线 | 独立新目录，只读报告一次并快照 |
